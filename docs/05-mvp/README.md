## Lecture indispensable

- **E0** est la démonstration sur deux Organizations et des données **fictives**.
- **E1** est un pilote réel **conditionnel**, nécessitant accords institutionnels et huit gates de sûreté.
- Les IDs de backlog ne sont pas des Issues GitHub déjà créées.
- Aucun sprint, estimation, fonctionnalité livrée ou résultat de test n'est revendiqué.
- Le parcours métier **qualifier -> responsabiliser -> suivre -> documenter -> transmettre -> exporter** doit être éprouvé, pas seulement modélisé.

Les capacités du MVP restent soumises à une validation produit. Le référentiel des 13 domaines cibles ne représente pas un engagement de réalisation simultanée.

Voir [Product Scope](../01-product/02-product-scope.md), [Requirements](../03-requirements/README.md), [plan de validation](../06-validation/00-pilot-validation-plan.md) et [politique de publication](../PUBLICATION-POLICY.md).
